# Workflow phases: idea to live

The twelve phases for building a new game (Mode A in `SKILL.md`). Open this when starting a game from an idea or checking which gate comes next. Paths are relative to the skill's root folder.

Work the phases in order. Each phase names its outputs, the reference to open and the gate that must pass before the next phase. Do not start a later phase on a system whose earlier gate failed.

| Phase | Outputs | Open | Gate |
|---|---|---|---|
| 1. Concept and genre | Pitch, fantasy, the one new verb, comparables, genre loop, age tier, platform priority | `references/market-scan-2026-11.md`, `references/genre-playbooks.md` then the one matching file in `references/genres/`, `references/case-studies-teardowns.md`, `references/design-foundations.md` §1–2 (the feeling, the fun) | Pitch fits one sentence; genre loop named; the new action or visible journey named; mobile-first confirmed |
| 2. One-pager, pillars and art direction | `templates/game-one-pager.md` filled; a one-page style bible and a reference board | `references/process-and-playtesting.md`, `references/design-foundations.md` §3 (paper loop rubric), `references/art-direction-and-quality-bar.md` §5–6 (reference board, style bible) | Paper loop rubric ≥ 7/10; three pillars are decision rules; the style bible has measurable rules |
| 3. Loops, FTUE and economy model | Loop spec with timings, first-minute script, `templates/economy-balance-sheet.md` filled with numbers | `references/core-loop-tuning.md` §1 (loop spec), `references/tutorial-and-onboarding.md` §2 (script format), `references/economy-and-progression.md` | Script has the first verb by 15 s, first reward by 30 s, first upgrade by 2 min and no offer; sink ratio 0.95–1.05 modelled; rebirth wait ratio ×1.2–1.5 |
| 4. Lean GDD and architecture plan | `templates/lean-gdd.md`; remotes list; data schema; products table; streaming and collision policy | `references/engineering-architecture.md`, `references/architecture-patterns-luau.md`, `references/gameplay-systems-cookbook.md`, `references/networking-and-security.md` ("Designing the network surface") | Gate 0 in `references/checklists.md` passes |
| 5. Build order and vertical slice | Project set up (Rojo, Script Sync or Studio-native: `references/studio-workflow.md` §8), loader, DataService, RemoteGuard, ReceiptService stubs; one playable loop with the Blender blockout kit | `references/engineering-architecture.md`, `references/studio-workflow.md`, `references/data-and-purchases.md`, `references/networking-and-security.md`, `references/debugging-and-testing.md` | Gate 1: five strangers; kill/keep decided (`templates/playtest-plan.md`). Gate 2 (engineering review) before this and every later release |
| 6. Game craft pass | Feel, camera, level layout, VFX, audio, AI, UI design, tutorial, cutscenes, settings and accessibility | `references/game-craft.md`, `references/level-design-worldbuilding.md`, `references/vfx-and-juice.md`, `references/vfx-recipes.md`, `references/audio-sfx-music.md`, `references/ui-design-figma.md`, `references/ui-screen-recipes.md`, `references/ui-motion-and-feedback.md`, `references/ui-input-crossplatform.md`, `references/tutorial-and-onboarding.md`, `references/cutscenes-and-cinematics.md`, `references/accessibility-and-player-qol.md`; reference images in `references/visual-library/` | Response times and juice tiers met; phone layout tested; greyscale and muted-play passes done; the UI, motion, effect and tutorial rubrics named in Gate 4 pass |
| 7. Art pipeline | Kit list, Blender assets → GLB → Open Cloud, post-import fixup, rigs and animation, lighting preset, art review against the style bible | `references/art-direction-and-quality-bar.md`, `references/blender-modeling-craft.md`, `references/art-pipeline-blender.md`, `references/animation-and-rigs.md`, `references/lighting-and-atmosphere.md` | Review gates in those files; the house-rule scan (`references/checklists.md`, Gate 4) prints OK in every place |
| 8. Monetization | `templates/monetization-product-plan.md`; products created; offer gate; receipts tested | `references/monetization-and-policy.md`, `references/data-and-purchases.md` ("Developer products: idempotent ProcessReceipt" onward) | Gate 3 compliance passes |
| 9. Analytics and LiveOps plan | `templates/analytics-event-plan.md`; Configs; Experiments; 4-week update plan; first event | `references/analytics-and-discovery.md`, `references/liveops-quests-retention.md` | Events verified in a test place |
| 10. Performance pass | MicroProfiler captures, budgets table filled, streaming settings, collision audit | `references/performance.md` | Gate 4 on a 2–4 GB Android phone |
| 11. Launch | `templates/launch-checklist.md` signed; icon, thumbnails, metadata, age tier, timing | `references/icons-thumbnails-and-store-page.md`, `references/analytics-and-discovery.md` ("Recommended For You", "Launch checklist"), `references/growth-and-marketing.md`, `references/community-moderation-safety.md`, `references/checklists.md` Gate 5 and the growth gate | All gates signed |
| 12. LiveOps | Fixed update day, events, season pass, funnel fixes, safety review | `references/liveops-quests-retention.md`, `references/analytics-and-discovery.md`, `references/growth-and-marketing.md`, `references/audit-existing-game.md` for a periodic level-up pass | "After launch (weekly)" in `references/checklists.md` done |

For a small request (one system, one bug, one balance tweak) skip to the matching row, but still check the gate for that row before declaring done.
