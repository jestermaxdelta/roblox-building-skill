# UI reference library: HUDs by genre and platform

What this is: 34 checked references for the heads-up display: hit Roblox games judged at phone size, commissioned Roblox HUDs by genre, shipped games outside Roblox whose layouts transfer, and the articles and tools behind them.
The rules these references support live in `references/ui-design-figma.md` §1 (the three reads), `references/ui-screen-recipes.md` §2 and §4 (HUD layouts, sizes) and `references/ui-input-crossplatform.md` (reserved zones, safe areas).

How to use this file:
- Pick your genre, open three rows (one from section 1, one from section 3), shrink each image to 800×360, and write down element count per screen region and what sits in read 1 before placing anything.
- Evidence: `viewed` = the image was downloaded and looked at; `read` = the page, thread or licence file was read; `oembed` = the video exists with that title and creator and was not watched; `search` = seen in search results only, not opened. `†` after the evidence word = the link is a Fandom `File:` page: it opens in a browser, but Fandom answers HTTP 403 to automated clients (curl, fetch tools), so an agent should download the `WK/…` image path given in the same row instead. Each such file was confirmed to exist through its wiki's `api.php` on 2026-11-11. Row numbers are stable ids that the guides cite: a removed row leaves a gap. Every link and image path was re-requested on 2026-11-11 (DevForum through its topic JSON, GitHub through `git ls-remote`): all answered except gameuidatabase.com, which this network cannot reach.
- These are references to study, not assets to copy: every screenshot, layout and kit stays its owner's. Copy the layout decision, never the art, logo or palette. Accessed 2026-11-11.

Image host prefixes: `DF` = `https://devforum-uploads.s3.dualstack.us-east-2.amazonaws.com/uploads/original`, `WK` = `https://static.wikia.nocookie.net`, `IIG` = `https://interfaceingame.com/wp-content/uploads`, `DOCS` = `https://prod.docsiteassets.roblox.com/assets`. `t/<id>` = `https://devforum.roblox.com/t/<id>`.

## Patterns seen across these references

- The number the loop is about sits bare on the world (icon + outlined number, no plate) in the references that read best when shrunk: #1, #6, #25, #24. A plate behind every number is a habit of the commissioned kits: #10, #11, #12.
- One home edge of icon + caption buttons survives a phone; two edges or a left column do not. Compare #3 (one edge) with #4, #11, #10, #12, where the left group meets the thumbstick.
- State lives next to its owner in the world, so the HUD shrinks: HP over heads, prices over items, cards in the arena (#9, #21, #22, #24, #26).
- Touch verbs form an arc round the right thumb and swap by context instead of adding buttons (#8, #21, #18).
- Corners and the top-centre carry state; the centre third stays empty in every action HUD (#7, #23, #24, #21).
- Element count tracks tempo: 3 in a calm game (#25), 6–8 in action games (#21, #7, #23), 10+ groups in simulators (#5, #10), which is where a phone arrangement becomes mandatory.
- Destination buttons own one colour and one word each, and keep both everywhere (#1, #10, #3).
- Hotbars live in the bottom-centre band between stick and jump button, numbered, in one case with the price under each slot (#17, #7, #4); text-only slots fail (#2, #6).
- Capacity and progress are written as have/need (`80/800`, `122/160`, `1/7`) beside the bar, never as a bar alone (#11, #24, #13).
- Timers on the HUD state a real remaining time for a real event (#3, #1): the honest form of urgency under house rule 3.
- Keyboard letters printed on buttons mark a desktop-first HUD; none of the touch-first references show them (#7, #12, #15 against #21, #8).
- The strong process references all block in regions on a real phone capture before drawing art (#19, #20, #18); peripheral reading depends on size, brightness and motion, not detail (#32).

## What the weak examples had in common

Drawn from the captures rejected or marked "badly" while building this file (megathread posts 25, 396 and 1274; threads t/794068, t/4967057, t/3077233 "before" image; rows #2, #4, #5, #16).

- A left column or a status stack sitting on the thumbstick zone, and hotbars running under the jump button: drawn on a desktop viewport and never opened on a phone.
- Buttons on two or three edges with equal size and saturation, so nothing is read 1.
- Text standing in for icons (hotbar labels, `Cash:` captions), and text a few px tall once the frame is shrunk to 800×360.
- A plate, a stroke and a glow behind every number; five flat buttons in five unrelated saturated colours with captions in a darker shade of the same hue.
- Default system font, default grey or translucent blue frames, coloured text on a translucent panel (the designer unroot shows his own early work in t/3077233 as the "before").
- Desktop-only density: chat, leaderboard, quest list and item list all docked at once, with no second arrangement for small screens.
- Glossy or neon styling applied to a HUD concept with no game behind it: the screenshot is a blurred backdrop, so nothing was tested against real contrast.
